# Método de trazabilidad y cierre
## Qué representa cada fila
criterion es criterio candidato original; task la tarea a la que pertenecía; workflow/situation/action/expected conservan términos existentes; origin permite revisar la versión fuente. evidence reproduce evidencia existente o señala que debe concretarse. execution siempre conserva NO_EJECUTADO.
references_original conserva literalmente la celda disponible. source_keys resuelve solo IDs explícitos de esa misma versión al catálogo; los rangos se expanden. No se asignó fuente por similitud de palabras ni una cláusula por deducción. Referencias a versiones previas/propuesta/local sin ID específico quedan pendientes de enlace manual.
legal_clause yowner están pendientes: no se evaluó cada criterio por artículo ni se designó autoridad institucional. Un criterio técnico puede necesitar justificación de ingeniería en lugar de obligación legal; registrar esa distinción cuando se revisa.
Tasks incluyen tablas candidatas v3–v8 con celdas originales. Algunas aceptaciones son narrativas, de migración o casosV2; no equivalen aCSV inexistente ni prueba realizada.
Catálogo contiene declaración de lectura heredada, no nueva visita a todas lasURLs. Agrupación exacta deURL detecta repeticiones, no versiones equivalentes: queries/rutas/ediciones pueden importar. No usar total de fuentes como métrica de calidad.

## Ficha mínima para aprobar una regla
- Servicio/flujo/contexto y evento real que exige control.
- Fuente/edición/fecha de publicación/vigencia, cláusula o sección exacta y lectura comprobada.
- Ámbito: privado/público, población, modalidad, institución/proveedor; conflictos/reformas resueltos por responsable.
- Decisión local: autoridad, SOP/contrato, datos y límites; base de ingeniería claramente marcada cuando corresponde.
- Criterio: precondiciones, acciones, resultado observable, error/excepción, evidencia yowner.
- Aceptación: revisión clínica/operativa/legal/técnica pertinentes y prueba en entorno autorizado; fecha/evidencia sin inventar.

## Gates separados
Lectura suficiente, aplicabilidad confirmada, política aprobada, diseño revisado, implementación verificada y aceptación operativa son estados separados. Se puede investigar/diseñar con pendientes visibles; no lanzar una regla clínica/legal como aprobada porque compiló.
Cierre de lectura requiere texto/sección, no ficha. Cierre institucional requiere documentos/observación/owner, no un dato promocional. Cierre técnico requiere pruebas pertinentes, no fixture que reproduzca implementación. Cierre operativo necesita proceso yresponsables reales.

## Conflictos y cambios
No editar historial v1–v8 para ocultar decisiones superadas. Crear decisión de reemplazo con razón, versión nueva, criterios afectados, datos/contratos/consumidores yacciones de migración. Los temas de privacidad2026/alta-costo/RTA y laboral ilustran impacto transversal.
Elaborar matrices de cláusulas por dominio primero; después vincular cada criterio. No toda cita sostiene toda una página. Añadir fragmento breve propio/verificable sin redistribuir manual protegido completo.
